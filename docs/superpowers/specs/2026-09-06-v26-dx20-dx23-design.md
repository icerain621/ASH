## Goal

Three themes from post-v2.5 backlog, sliced to shippable MVPs:

| Sprint | Theme | One-liner |
|--------|-------|-----------|
| **DX20** | tree-sitter symbols | `TreeSitterIndexer` on `SymbolIndexer`; `source=treesitter` |
| **DX21** | Sandbox harden | Landlock default-on (Linux capable) + minimal seccomp; M4-SBX-05 |
| **DX22** | Private skill packs | Signed pack install → `.ash/skills`; space allowlist |
| **DX23** | Single-region readiness | `ASH_REGION` + readyz + HA/backup runbook |
| **DX24** | Freeze | `v2.6-release-scope` frozen + `make v2.6-signoff` |

Tag `v2.6.0` remains **manual** after human sign-off.

- Public Skill Marketplace, ratings, billing, CDN

- Real embedding hard dependency; Chroma/Milvus adapters

## DX20 — tree-sitter SymbolIndexer

### Problem

DX16 ctags is optional and often missing on Windows CI; regex fallback is coarse. ARCH §6 already lists tree-sitter as a peer of ctags.

### Behavior

1. New `TreeSitterIndexer` implementing `SymbolIndexer` (`Name() == "treesitter"`).
2. **Implementation:** pure-Go parsers (no CGO): `go/parser`+`go/ast` for `.go`; structured extractors for `.ts`/`.tsx`/`.js`/`.jsx`; `yaml.v3` key walk for `.yaml`/`.yml`.
3. `ResolveSymbolIndexer()` preference:  
   `ASH_RAG_SYMBOL_INDEXER` override → else `ASH_RAG_CTAGS=0`→regex / `=1`→ctags / auto→**treesitter**.
4. Persist `rag_symbols.source` per file (`treesitter`|`ctags`|`regex`). Response `symbolSource` keeps preferred name if any file succeeded.
5. Unsupported extensions return error → per-file regex fallback.
6. Smoke: `rag-hybrid-smoke` includes treesitter package tests.

### Non-goals in DX20

- LSP client, hover, cross-file refs
- Background index daemon

### Acceptance

- Unit tests for indexer selection + at least one grammar parse
- `make rag-hybrid-smoke` green on Windows without ctags
- OpenAPI `symbolSource` enum docs updated if constrained

## DX21 — Landlock harden + minimal seccomp

### Problem

DX18 Landlock is opt-in (`ASH_SANDBOX_LANDLOCK=1`). Isolated runs still prefer Docker when available. No seccomp profile.

### Behavior

1. **Default preference (Linux + Available):**  
   `isolated` → `landlock` unless `ASH_SANDBOX_LANDLOCK=0` or Landlock unavailable → then docker → process (existing chain).
2. **Minimal seccomp** applied in landlock child (deny obvious dangerous syscalls; document allow/deny list; skip-pass on non-Linux / kernels without support).
3. Doctor **M4-SBX-05**: reports seccomp/landlock default path honesty (skip-pass off Linux).
4. Failure taxonomy: clear reason strings when landlock/seccomp apply fails → fall back, never silent deny of legitimate tools.
5. `sandbox-smoke` covers default-on path with env toggles.

### Non-goals in DX21

- E2B API client
- macOS Seatbelt / bwrap as first-class executors

### Acceptance

- Router unit tests for default / opt-out
- M4 suite +1 (ALL watermark bumps)
- `make sandbox-smoke` green (Windows: skip-pass semantics unchanged)

## DX22 — Private signed skill packs

### Problem

Sprint DN scans local `SKILL.md` only. PRD P3 “Skill Marketplace” is too large; need a **private distribution** shape that reuses plugin-sign trust.

### Behavior

1. Pack format: tarball/zip of skill dir + manifest (`name`, `version`, `digest`) + signature (align with `ash plugin-sign` / existing verify helpers where possible).
2. API (proposed):  
   - `POST /skills/packs/verify` (dry)  
   - `POST /skills/packs/install?repoRoot=` (verify → extract under `.ash/skills/<name>/`)  
   - Optional `GET /skills/packs` list of installed pack metadata if a small ledger table is justified
3. Space allowlist: install denied unless space policy / env allowlist permits publisher key id.
4. After install, existing `GET /skills` scan picks up the skill (no change to Run inject path).
5. `make skill-pack-smoke` + checklist.

### Schema

- Prefer **no new table** (filesystem + signature verify) for MVP.  
- If audit is required: `skill_pack_installs` (+SQL/RLS) — decide in DX22 task 1.

### Non-goals in DX22

- Public registry, search, ratings, payments
- Automatic remote update channel

### Acceptance

- Unsigned / bad-signature install fails closed
- Automation UI: install from file or path (minimal)
- openapi-check green

## DX23 — Single-region readiness (not multi-region AA)

### Problem

“Multi-region” as Active-Active is out of Stage 0–1. Operators still need a **region identity** and HA story for one region.

### Behavior

1. Config: `ASH_REGION` (string, default `local` / empty → `default`).
2. Surface on `GET /readyz` (and Scale/Obs watermark if cheap).
3. Docs: single-region HA + backup/restore pointers (reuse existing backup scripts); explicit “no cross-region replication in v2.6”.
4. No new Postgres topology requirements.

### Acceptance

- Unit/API test for region field
- Checklist section in v2.6 signoff
