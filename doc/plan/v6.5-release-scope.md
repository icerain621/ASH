## 1. 发布目标

把已有 GitHub Webhook 接到 v6.4 Ingress 缝：`ASH_INGRESS=webhook-github` 时先 `Accept`，失败则拒绝入库；默认 `null` 保持原 HMAC + CI 入库路径。不新增 IM 通道、不新表。  
Route the existing GitHub webhook through the v6.4 ingress seam when `ASH_INGRESS=webhook-github`. Default `null` keeps the current HMAC and CI ingest path. No new IM channel and no new table.

达到可打 **`v6.5.0`** 标签的功能水位（冻结后）。  
Reach the watermark for a manual **`v6.5.0`** tag (after freeze).

## 2. 包含范围（P0 · In）

| 域 | 交付物（Sprint） |
|----|------------------|
| 活路径 | HMAC 通过后，非 null 适配器 `Accept`；拒绝码 `INGRESS_REJECTED`（**VX51**） |

| 冻结 + 签字 | 本文件冻结；`make v6.5-signoff`（**VX52**） |

## 3. 不包含范围（本版本 Out）

- Hermes 全 IM、第二通道  
- 改变默认 `ASH_INGRESS`（仍为 null）  
- 新业务表、公网计费、Cordis / YOLO  

No second channel, and the default adapter stays null.

- 打 **`v6.5.0` tag** 前须签字 + `make v6.5-signoff` 绿
