## 1. 发布目标 / Release goal

进程内插件可登记并替换组件；自定义 Agent 模板先候选，评审通过后才能被运行绑定。暴露模板、组件、评审与 Pass^k、Context Pack 预览的 HTTP。  
In-process plugins can register and replace components. Custom agent templates stay candidates until review approves them for run binding. HTTP exposes templates, components, review/Pass^k, and Context Pack preview.

## 2. 包含范围（P5 · In）

| ID | 交付 |
|----|------|
| B02 | `plugins.Host` 支持 Tool / LoopPolicy / Compaction / Reviewer / Memory；可替换已登记 id |
| B03 | 保持 `pluginabi` 进程外命名；包注释写明与进程内宿主的区分 |
| B04 | 自定义模板：提交候选 → 评审批准 → `GetProduction` / 运行绑定 |
| B05 | Harness Profile `components` 清单；未批准组件不能 Activate |
| G02 | HTTP：模板候选、组件清单、评审决定、Pass^k、Context Pack 预览 + OpenAPI 路径 |
| H04 | 薄交付黄金路径：Context Pack 同时含记忆与 RAG |
| H05 | 未批准模板绑定运行被拒绝 |

模板与评审条目本波先进程内目录（与 P1 模板版本策略一致）。  
Template and review items stay in-process this wave (same as P1 template versions).
