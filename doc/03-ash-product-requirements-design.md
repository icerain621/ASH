# ASH 产品需求与设计文档（个人优先版）

## 1. 产品定位
- 产品名：ASH AI Platform
- 第一目标用户：个人开发者
- 扩展能力：支持团队空间管理
- 核心机制：记忆体（Memory Core） + 智能体（Agent Core）双核心协同
- 方向：偏工程自动化，服务日常软件交付全流程

## 2. 目标与边界
- 目标：把 ASK 从单点助手升级为可持续协作的 AI 工程平台
- 边界：先做 MVP，不做复杂组织治理与开放生态市场

## 3. 信息架构
- 工作台层：我的助理、团队空间
- 智能核心层：Memory Core、Agent Core
- 工程层：Repo、CI、Artifact、发布检查
- 知识扩展层：KBase、Skill、MCP
- 治理闭环层：Auth、Feedback、审计、看板

## 4. 核心功能（优先级）

### P0
- 个人工作台（任务、会话、执行历史）
- Memory Core（偏好、项目经验、可编辑治理）
- Agent Core（Planner/Executor/Reviewer）
- 工程自动化最小闭环（代码建议 -> CI 诊断 -> 修复建议）
- Feedback 基础闭环

### P1
- 团队空间管理（成员、权限、任务共享）
- MCP/Skill 管理（白名单、启停、日志）
- 自动交付检查与复盘报告

### P2
- 多 Agent 协同
- 团队级质量门禁
- 跨项目经验推荐

## 5. 双核心协同设计

### Memory Core
- 记忆类型：User / Project / Session
- 写入策略：显式确认 + 隐式候选
- 读取策略：任务初始化注入 + 过程按需检索
- 治理策略：TTL、置信度、可追溯来源

### Agent Core
- Planner：拆解任务与执行路径
- Executor：工具调用与动作执行
- Reviewer：结果校验、风险识别、下一步建议

### 协同闭环
- Agent 输出结构化结果 -> 写入 Memory
- Feedback -> 调整记忆置信度与执行策略

## 6. 工程自动化主链路
- 需求输入 -> 任务分解 -> 代码建议/改动 -> 测试建议 -> CI 诊断 -> 修复建议 -> 结果沉淀

## 7. 沿用 ASK 技术栈改造建议
- 保留：现有前后端、模型网关、数据层
- 新增服务：
  - `memory-service`
  - `agent-orchestrator`
  - `automation-gateway`
  - `feedback-service`

## 8. 主要开发功能点
- F1 个人工作台
- F2 任务编排引擎
- F3 记忆体管理
- F4 Repo/CI 集成与失败诊断
- F5 团队空间管理
- F6 MCP/Skill 管理
- F7 反馈系统
- F8 审计与可观测

## 9. 10 周开发计划（总览）
- W1-W2：架构与基线
- W3-W4：双核心 MVP
- W5-W6：工程自动化
- W7-W8：空间协作与反馈
- W9：联调与灰度
- W10：发布与复盘

## 10. 验收标准
- 可完成“需求 -> 执行 -> 诊断 -> 修复建议”闭环
- 记忆体可控，且能提升二次任务质量
- 团队空间可共享任务与上下文
- 指标可见：采纳率、成功率、任务时长、失败分布
